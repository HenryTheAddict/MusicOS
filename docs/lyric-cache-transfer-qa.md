# LyricsFile sync, quieter connections, playlist transfer — 2026-10-31

Isolated desktop branch: `codex/desktop-heart-preservation`. Android, audio protocol, embedded models/runtime, and the OS checkout stay separate.

## Behavior

- Metadata → Lyrics → Sync LyricsFiles saves selected/local or unambiguous cached lyrics offline as `song.lyricsfile.yaml`. No provider lookup and no unsaved-draft writes. Only affected lyric-session entries are invalidated after sync; no library rescan. Saved selections stay authoritative. Unknown fields, timing, and singers survive through canonical export.
- Apple matched lyric sync caches results and syncs LyricsFiles for those matched tracks. An existing externally edited sidecar is kept. Only unchanged files previously written by this sync can be updated, with a neighboring `.backup`; new files are published without replacing an existing path. Original audio and other metadata are untouched. Errors, missing lyrics, current files, and conflicts are counted separately.
- Apple setup is a compact optional connection row below Discord and Last.fm. The larger setup remains behind an explicit action.
- Explicit collection refresh reads playlist headers, selects the eight most recently updated, and caches those headers plus recent/heavy-rotation summaries. Track pages load only for an explicitly checked playlist. Unchanged checked sequences stay cached; display order follows the selected header ranking. Reopening the setup reads cache, not the provider. Sequential bounded pagination, cancellation, and cache retention on cancelled refresh are supported. These account endpoints remain experimental pending live account verification.
- Transfer creates a new local playlist only when every entry uniquely matches a currently available local file using signature-checked catalog links. Missing, ambiguous, unsupported, or duplicate entries block the entire transfer. The current local playlist schema cannot preserve repeat entries; none are silently removed. Names never overwrite an existing collection; repeat transfer preserves local edits. Apple receives no playlist writes or audio uploads/downloads.
- Home adds On repeat using real musicOS play counts. Apple recent/heavy-rotation summaries are labeled separately and never overwrite local counts or imply lifetime rankings. Album-only heavy rotation cannot be transferred as a fabricated song sequence.
- Sign-in now monitors completion for up to ten minutes while its private window exists. Cookie access is scoped by the Apple URL, rather than incorrectly rejecting valid parent-domain or host-only cookies. Apple-only authentication popups share the original private webview configuration. Successful verification closes auth windows and focuses musicOS. Cancellation invalidates pending verification; manual Check connection remains available. No external-browser cookies, manually supplied tokens, or passkey bypass.
